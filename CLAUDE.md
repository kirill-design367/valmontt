# CLAUDE.md — ВАЛЬМОНТ

> Контекст проекта. Читается автоматически при старте сессии.

## Что это

Сайт-приглашение на ВАЛЬМОНТ — вымышленное закрытое событие в альпийском
городке. Грифон — его герб. Кинематографический многостраничник: пять
маршрутов, кадр важнее функциональности. Снимается на видео и скриншотами
для соцсетей.

Планка — Awwwards Site of the Day. **Тест арт-директора:** мысленно убрать
всю анимацию и снять скриншот любого экрана — кадр должен держаться сам.
Движение не прикрывает композицию, а усиливает её.

Публикация: https://kirill-design367.github.io/valmontt/

## Стек

Next.js 15 App Router (`output: 'export'`) · React 19 · TypeScript ·
Tailwind v4 (токены через `@theme`) · GSAP + ScrollTrigger · Lenis.

**Three.js не подключён и не нужен.** В кадре снимок, типографика и тонкие
линии — всё это отдаёт композитор браузера. WebGL добавил бы контекст,
шейдерные компиляции и риск просадки на записи, не дав ни одного эффекта,
недостижимого на CSS и GSAP.

```bash
npm install
npm run dev        # http://localhost:3000/valmontt
npm run build      # статический экспорт в out/
npm run shoot      # скриншоты всех маршрутов + замер fps
npm run measure    # сверка геометрии hero с ТЗ
```

## Дизайн-система

### Шрифты — пара ролей

| Роль | Гарнитура | Веса | Где |
| --- | --- | --- | --- |
| `--font-display` | **Pilar Regular** | 400 — начертание одно | вордмарк, крупные заголовки, времена, имена зверей, номер билета |
| `--font-text` | **Onest** | 300, 400, 500 | навигация, лиды, подписи, кнопки, форма |

Pilar подключён **локальным файлом**, не через CDN: `public/fonts/pilar-regular.woff2`,
сабсет «кириллица + цифры + базовая пунктуация» (`scripts/subset-pilar.py`),
341 КБ → 45 КБ, preload. Стилистические наборы ss01–ss03 в сабсете сохранены.
Onest тянется из Google для интерфейса, без preload: в 11–15 px подмена
не читается.

**У Pilar одно начертание.** Синтетический жир запрещён глобально
(`font-synthesis-weight: none`), поэтому везде, где стоит акцидентный, вес
обязан быть 400 — массу набираем кеглем и трекингом, а не весом.

**Средний апрош слова ВАЛЬМОНТ у Pilar — 0.839 em против 0.728 у Onest**,
то есть на 15 % шире. Вся типографика пересчитана от этого числа; формула
столбца: `8 × (0.839em + трекинг) × кегль ≈ 110 % высоты экрана`.

На `/fonts` — четыре варианта вордмарка (базовый и ss01–ss03) и сравнение
заголовка hero: Pilar против Onest. Проверка состава глифов —
`scripts/audit-fonts.py`, геометрия столбца после смены гарнитуры —
`scripts/pilar-check.mjs` (сверяет фактический шаг с расчётным апрошем;
по названию семейства проверять нельзя — next/font подменяет его алиасом).

### Палитра

| Токен | Значение | Где живёт |
| --- | --- | --- |
| `--color-void` | `#07070a` | фон везде |
| `--color-bone` | `#ffffff` | весь интерфейс и текст |
| `--color-crimson` | `#c81e5a` | **единственный** акцент |

Малиновый — на точке корзины, индикаторе хронологии, ховере программы,
подсветке пустого поля формы. Больше нигде.

Бирюзовый и янтарный есть в оперении грифона, но **в UI их нет**. Цвет
приходит из снимка, а не из интерфейса.

### Сетка и отступы

- `--gutter`: 2.5rem десктоп / 1.35rem мобильная
- Секции: `clamp(7rem, 12vh, 11rem)` по вертикали. Воздух — часть кадра.
- Заголовок секции: `clamp(2.75rem, 3.6vw, 5.4rem)`, `line-height: 0.95`
- Лид: 13px / 300 / `rgba(255,255,255,.7)`
- Надпись-ярлык: 11px / 300 / трекинг `0.28em`

### Движение

| Что | Длительность | Кривая |
| --- | --- | --- |
| Вход hero целиком | 2.3 с | `power3.out` |
| Проявление по скроллу | 0.9–1.05 с | `power3.out` / `power4.out` |
| Штора перехода (в каждую сторону) | 0.5 с | `power3.inOut` |
| Переход между страницами целиком | ~1.3 с | — |
| Дыхание линзы | 4 с цикл | `sine.inOut` |
| Параллакс курсора | 1.1 с догон | `power3` |
| Ховеры | 0.4–0.5 с | `power3.out` / `--ease-out-quint` |
| Подчёркивание пункта меню | 0.3 с | `power2.out` (в CSS — `cubic-bezier(.215,.61,.355,1)`) |
| Выход бургера после обложки | 0.5 с / 0.35 с назад | `power3.out` / `power3.in` |

Линейных переходов на сайте нет.

### Фирменный приём

**Вертикальная типографика** (`writing-mode: vertical-rl`) — повторяется на
каждой странице минимум один раз: вордмарк hero, имена зверей, имя страницы
на шторе перехода, ярлыки секций.

## Законы проекта

1. **Латиницы в интерфейсе нет.** Только в именах переменных и классов.
2. **Вертикальная типографика не заменяется горизонтальной.** Нигде.
3. **Цветной акцент один — малиновый.** Новые цвета в UI не вводятся.
4. **Логотипов нет.** Вордмарк — это типографика, не логотип.
5. **Пара ролей неизменна:** акцидентный на вордмарк и крупные заголовки,
   нейтральный на интерфейс. Третью гарнитуру не вводим.
6. **Все недостающие изображения — в `lib/assets.ts`.** Подстановка
   настоящего файла = правка одной строки и ничего больше.
7. **Hero меняем только по прямой правке клиента** — и ровно в тех местах,
   которые он назвал. Обрезка вордмарка краями экрана не смягчается никогда.
8. **В покое в кадре не остаётся ни одного анимируемого фильтра.**
   Блюр только фиксированный, движение — `transform` и `opacity`.

## Планка качества

- 60 fps на всех анимациях и переходах — **замерять, а не декларировать**
  (`npm run shoot` сравнивает с потолком пустой страницы на том же рендерере)
- PageSpeed 90+, включая мобильную
- `prefers-reduced-motion` на всех страницах: переходы мгновенные,
  параллакс и циклы выключены
- Корректно на 1920×1080, 2560×1440, 390×844
- Мобильная версия каждой страницы — отдельная композиция, не сжатый десктоп
- Все пять маршрутов открываются по прямой ссылке без 404

## Принятые технические решения

**Рамка-линза привязана к снимку, а не к вьюпорту.** `lib/stage.ts` считает
прямоугольник, который `object-fit: cover` реально закрашивает, и публикует
`--eye-x` / `--eye-y` в пикселях. Рамка держится на глазу при любом
соотношении сторон. При замене снимка правится только константа `EYE`
(нормализованные координаты + фактический aspect файла).

**Блум вордмарка вынесен из параллакс-слоя.** Слой с `blur(54px)` внутри
движущегося поддерева пересчитывается каждый кадр и режет частоту вдвое.
Ореол размыт настолько, что отставание в 8 px не читается.

**Радиус блюра не анимируется нигде.** «Наведение на резкость» на входе —
перекрёстное затухание резкого текста и дубля с фиксированным блюром.
После входа дубль снимается из потока.

**Зерно запечено в подложку**, а не висит слоем поверх hero: полноэкранный
полупрозрачный слой пересобирается композитором каждый кадр параллакса.

**GSAP пишет свои значения в `transform`.** Поэтому центрирование
анимируемых элементов — флексом, а не `translate(-50%)`: иначе первое же
движение курсора сбрасывает смещение.

**Переход между страницами держит штору до готовности следующей страницы.**
Навигация не запускается, пока штора не закрыла экран; штора уходит только
после того, как новый маршрут отрисован. Белой вспышки нет by construction.

**Hero зафиксирован, страница едет поверх.** `position: fixed` + распорка в
100vh: блоки наезжают на hero, а не отталкивают его. Это же даёт «первый
экран без скролла внутри себя» при живом скролле страницы.

**Фон ленты блоков живёт на секциях, а не на обёртке.** Сплошная заливка на
`.flow` накрывает 100vh-распорку и вместе с ней зафиксированный hero — экран
становится чёрным. Ограничение ширины тоже вешается на строку, а не на
секцию: `max-width` на самой секции обрезает её фон, и сквозь блок
просвечивает hero.

**Кегль заголовков привязан к vw, а не только к rem.** «ПРИГЛАСИТЕЛЬНЫЙ» и
«ХРОНОЛОГИЯ» в верхнем регистре длиннее английских аналогов вдвое: на 390 px
фиксированный кегль даёт горизонтальный скролл. Общие классы `.t-page` и
`.t-block` в `globals.css` — единственное место, где это настраивается.

**Полноэкранные страницы просят `PageShell bare`.** Обычная рама добавляет
`padding-top` под шапку, и стопка липких экранов уезжает вниз на эту величину
вместе с подписями.

**Горизонтальный проезд `/mesto` живёт только на десктопе.** На телефоне pin
перехватывает нативный жест и скролл начинает драться сам с собой; там те же
четыре кадра идут вертикальной лентой — композиция кадра не меняется.

**Группы входа прячутся стилями, а не только прозрачностью.** `visibility`
снимается одним `tl.set` в начале таймлайна: анимировать `opacity` поверх
`visibility: hidden` недостаточно — элемент так и остаётся невидимым.

**Стекло линзы — испечённая картинка, а не `backdrop-filter`.** Замер
(`scripts/lens-perf.mjs`, три прогона, медиана) на прежней версии:

| сцена | fps |
| --- | --- |
| потолок пустой страницы | 61 |
| покой (рамка только дышит) | 60 |
| наведение, курсор неподвижен | 60 |
| **параллакс без участия линзы** | **47** |
| **наведение + параллакс** | **33** |
| то же, `backdrop-filter` снят | 43 |
| то же, дыхание заморожено | 35 |

Читается однозначно: сам таймлайн наведения и цикл дыхания бесплатны,
а `backdrop-filter` пересчитывал подложку в каждом кадре, где под ней ехал
параллакс, — это и есть −10 кадров. Заморозка масштаба не помогала.
Решение: `scripts/make-glass.py` печёт уменьшенную размытую копию подложки
(480 px десктоп / 300 px мобильная, 1–3 КБ), в браузере это обычная
картинка без единого фильтра, выровненная ровно по тому месту кадра, которое
рамка закрывает. Отсчёт от собственного начала координат линзы —
`calc(50% - var(--eye-x) - 24px)` по горизонтали, `30%` и `--viewport-h` по
вертикали, 24 px — запас `.bgLayer` под параллакс. После правки
«наведение + параллакс» = 41 при «параллаксе без линзы» = 43, то есть линза
не стоит ничего. Таймлайн, длительности и кривые не тронуты.

Ограничение замера: песочница рисует софтверным SwiftShader, поэтому
абсолютные числа занижены — сам параллакс здесь упирается в 43–47 кадров без
всякой линзы. Сравнивать имеет смысл только строки одного прогона.

**Кадры отдаются AVIF → WebP → JPEG через `<picture>`.** Подложки почти
чёрные с плавными переходами в тенях: JPEG на низком битрейте даёт там
ступеньки, AVIF держит градиент и весит вдвое меньше. Фон аватарок собран
через `image-set()` и снимается на телефоне совсем — иначе десктопный кадр
качался вхолостую и утяжелял LCP на 347 КБ.

**Кроп глаза для «Порога» режется заранее.** Масштабировать 2560-пиксельную
подложку в 4.6× прямо в браузере стоило двадцати кадров в секунду.

**Лента блоков не должна ловить клики за hero.** `.flow` лежит поверх
зафиксированного hero (z-index 1 против 0), поэтому `pointer-events: none`
на самой обёртке и `auto` на её детях, а распорка в 100vh остаётся сквозной.
Без этого первый экран накрыт наглухо: не кликаются ни навигация, ни линза,
ни пилюля, ни кружок. **Автотест `a.click()` этого не ловит** — он дёргает
обработчик напрямую, минуя hit-testing. Проверять только `mouse.click` по
координатам, как в `scripts/verify.mjs`.

**Вход hero снова целиком в GSAP.** Стоит 3 пункта мобильного Lighthouse и
0.4 с LCP — принято сознательно: анимацией не жертвуем. Таймлайн стартует
по событию `load` подложки, а не по готовности бандла.

**Специфичность бьёт цвет.** `.row > span` (0,1,1) перебивает `.crimson`
(0,1,0), и малиновая строка в линзе оставалась белой. Акцентные цвета внутри
типовых блоков вешать через `.row > span.crimson`.

**Пропорции вордмарка считаются, а не подбираются на глаз.** Шаг столбца =
(средний апрош Pilar 0.839em + трекинг) × кегль, восемь литер = восемь шагов.
Отношение столбца к высоте экрана и есть глубина среза: 116 % даёт по 8 %
сверху и снизу. Замер — `scripts/pilar-check.mjs`, он же роняет сборку, если
обрезка пропала. Текущие числа: десктоп 144.7 px / трекинг 35.5 px / столбец
114 % / срез 77 px; мобильная 92.8 / 37.1 / 107.5 % / срез 32 px.

**Ореол вордмарка задаётся в двух местах сразу.** Значения покоя лежат в
`.bloomNear` / `.bloomFar`, а таймлайн входа гонит прозрачность в те же
числа в `lib/motion.ts`. Меняя одно, править второе — иначе после входа
свечение прыгнет.

**Бургер живёт вне hero.** На обложке его нет: разделы стоят строкой сверху.
`components/HomeMenu.tsx` — фиксированная кнопка, которую ScrollTrigger
выводит после 0.75 высоты экрана и убирает при возврате наверх; она же
открывает панель разделов. Панель нужна не для красоты: ниже обложки верхняя
строка меню не видна, а на телефоне её нет вовсе — без панели навигация на
главной просто исчезала бы.

**`:root` внутри CSS-модуля не собирается.** css-loader требует «чистых»
селекторов — глобальные переопределения токенов живут только в
`app/globals.css` (там же мобильный `--gutter`).

## Открытые вопросы

- Три зверя из четырёх и все четыре кадра локации — заглушки
  (затемнённые кропы грифона). Ждут настоящих снимков; подстановка —
  одна строка в `lib/assets.ts`.
- Форма записи никуда не отправляется: сервера нет, static export.
  Номер приглашения генерируется на клиенте. При появлении бэкенда
  меняется только обработчик отправки.
- Тексты бестиария и хронологии — рыба уровня «правдоподобно»,
  не финальный копирайт.
- Скорость закрыта по решению клиента: живой замер 99 десктоп / 86 мобильная
  признан достаточным. Локально после возврата GSAP-входа — 73 мобильная,
  96 десктоп. Дальше не оптимизируем.
- fps: линза 60 в покое и при наведении, «Порог» 58, схлопывание 54 при
  потолке 61. Наведение с одновременным движением курсора упирается в
  параллакс hero (43 кадра в этой песочнице), сама линза при этом не стоит
  ничего.
- Живой PageSpeed не замерен: `github.io` закрыт egress-политикой песочницы.
  По той же причине не замерены живые fps — только локальные, на софтверном
  рендерере.

- Не менять hero сверх того, что клиент назвал в правке; пустоту от снятых
  элементов не заполнять
- Не смягчать обрезку вордмарка краями экрана
- Не жертвовать анимациями ради скорости — скорость закрыта
- Не добавлять секции сверх описанных в ТЗ
- Не вводить латиницу в интерфейс
- Не заменять вертикальную типографику горизонтальной
- Не добавлять цветных акцентов кроме малинового
- Не ставить логотипов, не менять шрифт
- Не возвращать правило «строго 100vh» — оно снято для всех страниц,
  кроме самого hero как первого экрана
